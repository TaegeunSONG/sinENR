# SinENR — explicitly-parameterized neural representation with a sinusoidal basis

*This repository holds the code and the per-seed result tables. The manuscript
sources and the compiled documents are not part of the release, and the
rendered figures are not committed either, because the scripts here regenerate
them.*

SinENR is a single-hidden-layer perceptron with a sine activation,

```
y_hat(x) = b2 + sum_j  W2_j * sin( W1_j * x + b1_j )
```

in which each hidden unit *is* one sinusoidal component: after training, the
triplet `(W1_j, b1_j, W2_j)` is read directly as the frequency, phase and
amplitude of a component of the signal. No post-hoc attribution step is
involved — the weights are the spectral report.

The paper has two halves. The first fits this model and benchmarks the readout.
The second asks when the fitted parameters mean what they appear to mean, and
shows that on a uniform grid they are identifiable only modulo an alias group
generated by the sampling rate — a degeneracy that training loss, validation
loss, multi-start selection and early stopping are all blind to.

## Two results worth stating up front

1. **Classical parametric estimators are the more accurate ones on the
   synthetic benchmarks.** Given the true model order, nonlinear least squares,
   MUSIC, ESPRIT and the matrix pencil all recover continuous-valued
   frequencies, and on signals that are exact superpositions of a known number
   of tones they beat SinENR — by eleven orders of magnitude on the noiseless
   two-tone benchmark. The contribution here is therefore not accuracy beyond
   the Fourier grid, which is classical, but the explicit parameterization and
   the identifiability analysis. `benchmark_baselines.py` runs the comparison.
2. **The close frequency pair in the islet readout is not two physical modes.**
   Five diagnostics (natural frequencies of the generating oscillators, an 8×
   longer trajectory, a record-length sweep, a penalty and model-order sweep,
   and a bootstrap) agree that the dominant cluster is one broad band
   represented by a few atoms whose individual positions move with record
   length and penalty. `islet_robustness.py` runs all five.

Throughout the code and the tables, "estimation error" means $|\hat f - f|$ and
is kept distinct from spectral resolution, and the Fourier reference scale is
named as the DFT grid spacing $1/L$.

## Reproducing the numbers

Requires Python 3.11+ and the packages in `requirements.txt` (`pip install -r
requirements.txt`). CPU is sufficient; every run below takes minutes, not hours.
The figure scripts write `fig*.pdf` and `fig*.png` into the repository root;
those outputs are not committed.

```bash
python benchmark.py             # tasks A/B/C -> results/results_raw.csv, results_summary.csv
python benchmark_extra.py       # contiguous-gap and lambda sweeps
python benchmark_baselines.py   # NLS / MUSIC / ESPRIT / matrix pencil on tasks A, B, C
python alias_analysis.py        # alias capture vs frequency prior bound
python islet_robustness.py      # the five close-pair checks (~3 min)

python make_figdata.py                  # fits behind Figs. 2 and 3 (~3 min)
python make_fig_missing.py              # Fig. 4 (refits; ~1 min)
python make_fig_islet_robustness.py     # Fig. 6
python make_figures.py                  # Figs. 1-3, 5, 7
```

`make_figdata.py` writes `figdata.npz`, `figdata_denoise.npz` and
`alias_landscape.npz`, the per-fit arrays that `make_figures.py` reads for the
panels that are not summarised in a CSV. Those caches are regenerable and not
committed. Run `make_figures.py` last: it and `make_fig_benchmark.py` both
write `fig3_benchmark.pdf`, and the later run wins.

Every script routes its randomness through an explicit seed, so the reported
values reproduce exactly. The tables in `results/` are the ones behind every
number in the manuscript; nothing in the paper is computed outside this
repository.

## The islet model: what differs from the original Fortran

The equations, parameters, RK4 integrator and sampling interval are those of
the original in every version here. The random number generation is not, in
two places, and both are deliberate.

`islet_model.py` uses a seeded PCG64 generator so that a run is reproducible,
where the original seeded Numerical Recipes routines from the system clock, and
it can discard a burn-in interval, which the original driver does not.

`islet_module.f90` and `islet_trace.f90` as released here have had those
Numerical Recipes routines (`ran1`, `gasdev`) replaced, because that code is
copyrighted and cannot be redistributed. The substitutes are Marsaglia's
xorshift64 for uniform deviates and the Marsaglia–Bray polar method for normal
deviates, in double precision, behind the same interface — no call site
changed. Over 2×10⁶ draws they give uniform mean 0.49992 and variance 0.08337
(against 0.5 and 1/12) and normal mean −0.0004 and variance 1.0012.

A trajectory from either released version is therefore statistically
equivalent to, but not bit-identical with, one from the authors' original
Fortran. "Statistically equivalent" is measured rather than asserted:
`compare_port.py` runs both implementations 50 times and compares the
distributions of three trajectory statistics with a two-sided
Kolmogorov–Smirnov test.

| quantity | Fortran | Python | KS *p* |
|---|---|---|---|
| trajectory s.d. | 0.2482 ± 0.0521 | 0.2361 ± 0.0534 | 0.112 |
| peak frequency (interpolated) | 0.1611 ± 0.0172 | 0.1640 ± 0.0233 | 0.998 |
| spectral centroid | 0.1886 ± 0.0104 | 0.1882 ± 0.0109 | 0.998 |

None of the three separates the implementations. The grid-level dominant bin
is reported by the script too but is not tested: at 1/L = 0.0134 it can take
only a handful of values, and a KS test on a statistic that discrete is not
meaningful. Its counts are nearly identical anyway (24/24 trajectories at
0.160, 19/16 at 0.173). The Fortran seeds itself from the wall clock, so its
side of the comparison is not reproducible run to run.
